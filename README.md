# Сервис управления подписками на уведомления

## Назначение
Приложение позволяет пользователям управлять подписками на различные типы
уведомлений (email, push, SMS), настраивать частоту получения уведомлений
и отслеживать статус каждой подписки (активна, приостановлена, истекла).
В дальнейшем сервис будет развернут как веб-приложение с личным кабинетом
пользователя и API для сторонних сервисов, интегрирующих отправку уведомлений.

## Целевая аудитория
- пользователи веб- и мобильных сервисов, желающие гибко настраивать,
  какие уведомления и по каким каналам они получают;
- администраторы сервисов-интеграторов, которым нужно управлять рассылками
  и контролировать статус подписок пользователей.

## Предметная область
Управление подписками пользователей на уведомления: регистрация подписки,
выбор канала доставки (email, push, SMS), выбор типа уведомлений (новости,
акции, системные оповещения), контроль срока действия подписки и её
текущего статуса.

## Основные сущности
- Подписчик (Subscriber) — пользователь, оформивший подписку
- Подписка (Subscription) — связь подписчика с типом уведомлений и каналом
- Тип уведомления (NotificationType) — категория рассылки (новости, акции,
  системные оповещения)
- Канал доставки (DeliveryChannel) — email, push, SMS

## Основные функции
- проверка статуса подписки (активна / истекла / приостановлена)
- расчёт количества дней до окончания срока действия подписки
- формирование текста уведомления для подписчика
- валидация email-адреса подписчика при оформлении подписки

## Возможности (ПР2)
- учёт нескольких подписчиков, типов уведомлений и подписок;
- добавление и поиск подписчиков и типов уведомлений;
- сортировка типов уведомлений;
- оформление подписки с запретом повторной активной подписки на тот
  же тип и канал;
- приостановка подписки без удаления записи из истории;
- просмотр статуса и формирование уведомления по конкретной подписке;
- хранение данных между запусками в JSON-файлах.

## Объектная модель (ПР3)

Предметная область представлена тремя классами пакета `models/`:

### NotificationType — тип уведомлений
Атрибуты: `id`, `name`. Метод: `__str__()`.

### Subscriber — подписчик
Атрибуты: `id`, `name`, `email`.
Методы:
- `validate_email(email)` (`@staticmethod`) — функция из ПР1, проверка
  формата email;
- `from_data(data)` (`@classmethod`) — создание подписчика из словаря
  (например, при загрузке из JSON);
- `__str__()` — строковое представление.

### Subscription — подписка
Связывает объекты `Subscriber` и `NotificationType` через канал
доставки. Атрибуты: `id`, `subscriber`, `notification_type`,
`channel`, `end_date`, `is_active`.
Методы:
- `cancel()` — приостанавливает подписку (объект остаётся в истории);
- `days_until_renewal(current_date)` — функция из ПР1, количество
  дней до окончания;
- `get_status(current_date)` — вызывает сохранённую без изменений
  функцию `check_subscription_status()` из ПР1;
- `format_notification(current_date)` — функция из ПР1, текст
  уведомления для подписчика;
- `__str__()` — строковое представление с учётом статуса.

`Subscription` хранит ссылки на сами объекты `Subscriber` и
`NotificationType`, а не только их идентификаторы, поэтому связанные
данные доступны напрямую: `subscription.subscriber.name`,
`subscription.notification_type.name`.

## Структура проекта
```text
fr1/
├── README.md
├── requirements.txt
├── setup.cfg
├── pytest.ini
├── main.py
├── storage.py
├── utils.py
│
├── models/
│   ├── __init__.py
│   ├── notification_types.py
│   ├── subscribers.py
│   └── subscriptions.py
│
├── data/
│   ├── subscribers.json
│   ├── notification_types.json
│   └── subscriptions.json
│
└── tests/
    ├── test_subscribers.py
    ├── test_notification_types.py
    └── test_subscriptions.py
```

- `main.py` — точка запуска, меню приложения, пользовательские сценарии;
- `models/subscribers.py` — класс `Subscriber` и функции
  `add_subscriber`, `find_subscriber`, `find_subscriber_by_id`;
- `models/notification_types.py` — класс `NotificationType` и функции
  `add_notification_type`, `find_notification_type`,
  `find_notification_type_by_id`, `sort_notification_types`;
- `models/subscriptions.py` — класс `Subscription`, сохранённая функция
  `check_subscription_status()` и функции `is_subscription_active`,
  `create_subscription`, `cancel_subscription`;
- `storage.py` — преобразование JSON <-> объекты;
- `utils.py` — безопасный ввод чисел, дат и канала доставки;
- `data/` — файлы данных;
- `tests/` — автоматизированные тесты.

## Требования
- Python 3.10+;
- pytest;
- flake8.

Установка зависимостей:
```
pip install -r requirements.txt
```

## Запуск программы
```
python main.py
```

## Запуск тестов
```
pytest -v
```

Тесты проверяют создание и поведение объектов `NotificationType`,
`Subscriber` и `Subscription`, методы классов, запрет повторной
активной подписки на тот же тип и канал, отмену подписки и работу
сохранённых функций ПР1 (`validate_email`,
`check_subscription_status`, `days_until_renewal`,
`format_notification`).
