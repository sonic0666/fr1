# Шпаргалка к защите ПР5–ПР7 (NotifyHub)

## Как работает всё вместе (одним абзацем)
Браузер отправляет запрос, например `GET /subscriptions/2/`. Django берёт
корневой `notifyhub/urls.py`, по префиксу `subscriptions/` через `include()`
передаёт запрос в `subscriptions/urls.py`, где `<int:subscription_id>/`
выбирает view `subscription_detail`. View открывает соединение с SQLite,
выполняет SQL-запрос с параметром `?`, кладёт результат в словарь `context`
и вызывает `render(request, "шаблон.html", context)`. Шаблон наследуется от
`base.html`, подставляет данные и возвращается браузеру как HTML.

```
запрос -> notifyhub/urls.py -> app/urls.py -> view -> SQL (db/queries.py)
       -> context -> шаблон (extends base.html) -> HTML-ответ
```

## ПР5. Основы Django

| Вопрос | Ответ |
|---|---|
| Что такое Django? | Веб-фреймворк на Python: маршрутизация, шаблоны, ORM, админка, безопасность «из коробки». |
| Проект и приложение? | Проект (`notifyhub`) - настройки и корневые маршруты. Приложение (`homepage`, `notification_types`, `subscriptions`) - логически законченная часть сайта. Создаётся `startapp`, подключается в `INSTALLED_APPS`. |
| Что делают `manage.py`, `settings.py`, `urls.py`? | `manage.py` - команды (`runserver`, `check`, `migrate`); `settings.py` - конфигурация; `urls.py` - таблица «адрес -> view». |
| Что такое view? | Функция, которая принимает `request` и возвращает `response` (у нас через `render`). |
| Как работает маршрутизация? | `path("types/", include(...))` - префикс; в приложении `path("<int:type_id>/", view, name="detail")`. Конвертер `<int:...>` пропускает только число и передаёт его во view аргументом. |
| Зачем `include()`? | Чтобы каждое приложение держало свои маршруты в своём `urls.py`. |
| Зачем `app_name`? | Пространство имён: `notification_types:detail` не конфликтует с `subscriptions:detail`. |
| Как обработать 404? | В view: `render(..., status=404)`; для неизвестных адресов - `handler404 = "homepage.views.page_not_found"` в корневом `urls.py`. Своя страница работает при `DEBUG=False`. |
| Что в `settings.py` менялось? | `INSTALLED_APPS` (+3 приложения), `ALLOWED_HOSTS`, `LANGUAGE_CODE='ru-RU'`, `TIME_ZONE='Europe/Moscow'`, `TEMPLATES['DIRS']`. |
| Как запустить? | `pip install -r requirements.txt`, `python manage.py migrate`, `python manage.py runserver`. |

## ПР6. Шаблоны Django (DTL)

| Вопрос | Ответ |
|---|---|
| Зачем шаблоны? | Отделяют HTML от Python-логики: view готовит данные, шаблон отображает. |
| Что такое контекст? | Словарь, который view передаёт в `render()`; ключи доступны в шаблоне как переменные: `{{ notification_type.name }}`. |
| Наследование шаблонов? | `base.html` с блоками `{% block title %}` и `{% block content %}`; дочерний шаблон начинается с `{% extends "base.html" %}` и переопределяет блоки. |
| `include` и `extends` - разница? | `extends` - «я часть этого каркаса»; `include` - вставить готовый фрагмент (навигация, карточка типа, статус подписки). |
| Теги | `{% for %}…{% empty %}…{% endfor %}`, `{% if %}/{% elif %}/{% else %}`, `{% url 'ns:name' arg %}`, `{% load static %}`, `{% static 'путь' %}`. |
| Фильтры | `\|length` (количество), `\|default:"Без названия"`, `\|date:"d.m.Y"` (формат даты). |
| Зачем `{% url %}`, а не жёсткий адрес? | Адрес меняется в одном месте (`urls.py`), ссылки обновляются сами. |
| Статические файлы? | Лежат в `<app>/static/<app>/`, подключаются через `{% static %}`; CSS (стили), JS (год в подвале), PNG (логотип). |
| Где Django ищет шаблоны? | В `TEMPLATES['DIRS']` (`templates/`) и в `<app>/templates/<app>/` (`APP_DIRS=True`). Подпапка с именем приложения нужна, чтобы имена не пересекались. |
| Автоэкранирование? | Django экранирует `<`, `>` в `{{ }}` - защита от XSS. |

## ПР7. SQL и SQLite

| Вопрос | Ответ |
|---|---|
| Что такое БД, СУБД, SQL? | БД - упорядоченное хранилище данных; СУБД - программа для работы с ней (SQLite); SQL - язык запросов. |
| Почему SQLite? | Файловая БД без сервера, входит в Python (`sqlite3`), удобна для учебных проектов. |
| Таблицы проекта | `notification_types`, `subscribers`, `subscriptions` (`sql/schema.sql`). |
| Первичный ключ? | `id INTEGER PRIMARY KEY` - уникально идентифицирует строку. |
| Внешний ключ? | `subscriptions.subscriber_id -> subscribers.id`, `type_id -> notification_types.id`: нельзя создать подписку на несуществующего подписчика/тип. Включается `PRAGMA foreign_keys = ON` (в SQLite по умолчанию выключен). |
| Типы связей | Один подписчик - много подписок; один тип - много подписок. |
| Ограничения | `NOT NULL`, `DEFAULT 1`, `CHECK (channel IN ('email','push','sms'))`, `CHECK (is_active IN (0,1))`. |
| Как создали и заполнили БД? | `executescript(schema.sql)`, затем `python -m db.import_json` (JSON -> таблицы через `executemany`; сначала родительские таблицы; `commit`, при ошибке `rollback`). |
| Параметризованные запросы | `execute("... WHERE id = ?", (type_id,))` - значение передаётся отдельно, защита от SQL-инъекций. Нельзя собирать запрос f-строкой. |
| `row_factory = sqlite3.Row` | Строка доступна по имени колонки (`row["name"]`), в шаблоне - `{{ row.name }}`. |
| `WHERE` и `HAVING` | `WHERE` фильтрует строки до группировки, `HAVING` - группы после `GROUP BY` с агрегатами. |
| `JOIN` и `LEFT JOIN` | `JOIN` - только совпавшие строки; `LEFT JOIN` - все строки левой таблицы (типы без подписок тоже, с `COUNT = 0`). |
| Агрегатные функции | `COUNT`, `MIN`, `MAX` (используются в статистике). |
| Подзапрос `NOT IN` | Страница «Доступные типы»: типы, которых нет среди активных подписок подписчика на дату. |
| `commit` / `rollback` | Подтвердить / отменить все изменения транзакции. |
| Как хранятся даты? | Текстом ISO `ГГГГ-ММ-ДД`: сравнение строк даёт верный порядок дат (`end_date >= ?`). В Python - `date.fromisoformat`. |
