## 3. Доработка индивидуального проекта

- **Название проекта:** Сервис управления подписками на уведомления
- **Репозиторий:** https://github.com/sonic0666/fr1 (коммиты
  `PR3: add NotificationType, Subscriber and Subscription classes in
  models package` и `PR3: adapt main.py, storage.py, README and
  tests to the object model`)

**Основные классы (пакет `models/`):**

| Класс | Атрибуты | Методы |
|---|---|---|
| `NotificationType` | `id`, `name` | `__str__()` |
| `Subscriber` | `id`, `name`, `email` | `__str__()`; `validate_email()` (`@staticmethod`, функция из ПР1); `from_data()` (`@classmethod`) |
| `Subscription` | `id`, `subscriber`, `notification_type`, `channel`, `end_date`, `is_active` | `cancel()`; `days_until_renewal()` (функция из ПР1); `get_status()` (вызывает сохранённую `check_subscription_status()` из ПР1); `format_notification()` (функция из ПР1); `__str__()` |

**Краткое описание доработки:**

- словари и списки словарей заменены на списки объектов
  (`list[Subscriber]`, `list[NotificationType]`,
  `list[Subscription]`);
- `Subscription` хранит ссылки на сами объекты `Subscriber` и
  `NotificationType`, а не только их идентификаторы — данные
  доступны напрямую (`subscription.subscriber.name`);
- операции, относящиеся к конкретному объекту
  (`days_until_renewal`, `get_status`, `format_notification`,
  `cancel`), перенесены в методы класса `Subscription`; функции
  работы с целой коллекцией (`add_subscriber`, `find_subscriber`,
  `create_subscription` и др.) остались обычными функциями модулей;
  функция `check_subscription_status()` сохранена без изменений;
- `storage.py` адаптирован: загрузка создаёт объекты, связывая
  `Subscription` с уже загруженными `Subscriber`/`NotificationType`
  по идентификаторам; сохранение возвращает объекты к
  идентификаторам в JSON;
- `main.py` переписан на работу с объектами вместо словарей;
- тесты (`tests/`) адаптированы под объектную модель — 24 теста,
  проверяют создание объектов, атрибуты, методы, запрет повторной
  активной подписки, отмену подписки и работу сохранённых функций
  ПР1;
- обновлён `README.md`: описаны классы, атрибуты, методы,
  взаимодействие объектов и структура проекта.

## 4. Результат работы

- основные сущности проекта представлены классами
  (`Subscriber`, `NotificationType`, `Subscription`);
- реализованы атрибуты и методы классов, конструктор `__init__` и
  строковое представление `__str__`;
- продемонстрировано использование `@staticmethod` и `@classmethod`;
- организовано взаимодействие объектов через ссылки (`Subscription`
  → `Subscriber`, `Subscription` → `NotificationType`);
- существующая функциональность ПР2 полностью сохранена и
  адаптирована к объектной модели;
- данные по-прежнему хранятся в JSON и корректно преобразуются в
  объекты и обратно;
- сохранена обработка исключений и проверка ввода;
- все 24 автоматизированных теста проходят, `flake8` — без
  замечаний;
- результат зафиксирован в Git отдельными коммитами с меткой `PR3:`.

## 5. Вывод

В ходе выполнения ПР3 функциональная модель проекта, построенная на
словарях и списках в ПР2, переработана в объектно-ориентированную:
предметная область представлена тремя классами с атрибутами и
методами, организовано их взаимодействие через прямые ссылки между
объектами. Все функции, унаследованные от ПР1
(`validate_email`, `check_subscription_status`, `days_until_renewal`,
`format_notification`), сохранены и переиспользуются внутри методов
класса `Subscription`, что подтверждает последовательность развития
проекта на всех трёх этапах. Проект готов к дальнейшему развитию —
переходу к веб-приложению на Django.
